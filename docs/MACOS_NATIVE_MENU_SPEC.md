# macOS 原生菜单开发规范

- 版本：0.1
- 日期：2026-08-24
- 适用范围：macOS“仓库”“动作”“窗口”菜单

本文定义原生菜单的信息架构、行为契约、状态边界和验收方法。交付优先级、任务状态与版本归属只在
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) 维护；本文不是第二份路线图。

## 1. 目标与边界

菜单应尽量沿用 Sourcetree 公开可观察的信息层级和桌面交互语义，但所有行为由本项目独立实现。
不得复制 Sourcetree 的源码、资源、专有文案、私有接口或未公开行为。

统一边界如下：

- Git CLI 和重新读取的仓库状态是唯一事实来源；菜单缓存只用于启用状态，不能覆盖 Git 结果。
- 仓库和动作菜单只作用于当前 key workspace，不得回退到最近使用或后台仓库。
- 首页不是隐式 Git 操作目标。没有前台工作区时，依赖仓库的菜单项必须禁用。
- UI 不拼接或执行 Git 命令。Git 操作统一进入应用层和 `GitRunner`，写操作结束后必须刷新状态。
- 未交付入口保留“（待实现）”后缀，只显示“该菜单功能待实现”，不得启动 Git、文件或窗口操作。
- 危险操作先展示目标、影响范围和不可恢复内容，再由用户明确确认；默认选择必须是安全模式。
- 原生窗口操作由 AppKit 完成；仓库、引用、索引和工作区操作由 Flutter 应用层完成。

## 2. 当前实现基线

### 2.1 调用链

```text
MainMenu.xib
  → AppDelegate @IBAction / validateMenuItem
  → WindowCoordinator.currentWorkspaceController
  → WorkspaceFlutterWindowController.performWorkspaceAction
  → MethodChannel: workspaceAction
  → DesktopWindowBridge
  → _RepositoryWorkspaceScreenState._handleWorkspaceMenuAction
  → RepositorySessionController / Dialog / WindowCoordinator
```

关键文件：

- `macos/Runner/Base.lproj/MainMenu.xib`：菜单层级、标题、快捷键和原生 selector。
- `macos/Runner/AppDelegate.swift`：key window 定位、菜单校验、AppKit 动作和 MethodChannel 路由。
- `lib/src/app/desktop_window_bridge.dart`：每个 Flutter Engine 独立注册菜单回调。
- `lib/src/app/git_desktop_app.dart`：工作区菜单分发、对话框和应用层调用。

`WindowCoordinator.currentWorkspaceController` 只接受当前 `NSApp.keyWindow` 且角色为 workspace 的
窗口。该约束是多窗口安全不变量，后续不得以 MRU workspace 或最后打开的仓库代替。

### 2.2 已有行为

| 菜单 | 已交付 | 当前待实现行为 |
| --- | --- | --- |
| 仓库 | “仓库详情…”读取并展示当前仓库的真实 Git 统计 | 其余入口带“（待实现）”，仅在前台工作区可点击并提示待实现 |
| 动作 | “创建补丁…”和“应用补丁…” | 其余入口带“（待实现）”，仅在前台工作区可点击并提示待实现 |
| 窗口 | 系统最小化/缩放/置前/窗口列表；显示仓库浏览器；合并所有工作区窗口 | 平铺、显示器、窗口组、远端仓库和标签页入口带“（待实现）”，在首页或工作区显示原生提示 |

仓库和动作的待实现项共用 `repositoryFeaturePendingFromMenu:`；窗口待实现项使用不依赖仓库的
`windowFeaturePendingFromMenu:`。正式开发某一项时，应为它分配稳定的语义 action ID；不得通过
菜单标题判断业务行为。

## 3. 通用行为契约

### 3.1 目标窗口与上下文

菜单打开和点击时都必须重新解析上下文：

1. AppKit 读取当前 key window。
2. 仓库/动作项要求 key window 为仍存活的 workspace。
3. Flutter 侧再次确认仓库已加载、选择仍有效且 Widget 未销毁。
4. 涉及写入时，应用层在执行前按最新 Git 状态重新校验前置条件。
5. 窗口关闭、Engine 关闭或 key window 切换后，旧回调和旧状态立即失效。

文件、提交、分支和贮藏等“选中项”均来自当前 workspace 的可见选择。若焦点位于不支持该动作的
区域，菜单项应禁用，不能沿用此前页面的隐藏选择。

### 3.2 启用、禁用与待实现

三种状态必须明确区分：

| 状态 | 显示 | 点击结果 |
| --- | --- | --- |
| 已实现且可用 | 正常标题 | 执行对应工作流 |
| 已实现但当前不可用 | 正常标题、禁用 | 不响应；可通过帮助文本解释缺少仓库、选择、upstream 或安全条件 |
| 未实现 | 标题包含“（待实现）” | 仅显示统一提示，不产生任何副作用 |

实现完成后必须同时移除“（待实现）”、接入独立 action ID、补充动态校验和测试。不能只改标题或
复用一个与菜单语义不一致的现有动作。

### 3.3 动态菜单状态

最终实现应由 Flutter 工作区生成只读 `WorkspaceMenuState` 快照，并按 Engine/窗口隔离发送给
AppKit。快照至少包含：

- 仓库是否就绪，是否为空仓库、bare repo 或 detached HEAD。
- 当前分支、upstream、ahead/behind、远端可用性。
- staged/unstaged/untracked/conflicted 计数和当前选择类型。
- merge/rebase/cherry-pick/revert 等进行中操作。
- 当前 Git 任务是否占用写队列，以及 Engine generation 是否仍有效。

`validateMenuItem` 只读取当前 key workspace 的快照以提供即时禁用状态；真正执行仍由应用层根据
最新状态二次校验。快照缺失、过期或窗口正在关闭时按不可用处理。

### 3.4 异步、取消与反馈

- 菜单动作不得阻塞 AppKit 主线程或 Flutter UI isolate。
- 同一仓库的 Git 写操作进入现有操作队列；冲突类操作不能并发启动另一个写操作。
- Fetch、Pull、Push 和外部进程显示运行、认证等待、取消、成功、失败或结果不确定状态。
- 对话框关闭、窗口关闭和 Engine 销毁必须取消或失效异步回调，禁止销毁后更新 UI。
- 每次 Git 写操作无论成功、失败或取消，都重新读取工作区、引用和进行中操作状态。
- 错误反馈保留可行动的 Git 原因，同时继续遵守凭据和远端 URL 脱敏规则。

## 4. “仓库”菜单规格

“仓库”菜单用于仓库级工作流，不依赖文件列表中的具体右键目标。能复用工具栏或现有对话框的
入口必须调用同一应用层用例，不能复制 Git 命令和状态判断。

### 4.1 信息与刷新

| 菜单项 | 行为契约 | 启用条件与执行层 |
| --- | --- | --- |
| 仓库设置… | 打开当前仓库设置；只能修改明确展示的仓库级偏好，不静默修改 global/system Git 配置 | 仓库已加载；Flutter 设置用例 |
| 仓库详情… | 展示提交、引用、文件、作者、LFS 提示和本地占用；空仓库安全降级 | 已交付；仓库已加载；Flutter 只读查询 |
| 刷新 | 取消/失效旧读取后重新读取本地状态、引用、历史首屏和当前详情 | 仓库已加载且未关闭；Flutter 只读刷新 |
| 刷新远程仓库状态 | 语义冻结前不得等同于 Fetch。实现时需明确是只读远端探测还是更新本地远端引用 | 远端存在且无冲突任务；应用层远端用例 |

### 4.2 提交与同步

| 菜单项 | 行为契约 | 启用条件与风险 |
| --- | --- | --- |
| 提交… | 打开现有提交面板，保留 staged/unstaged、Amend 和 hooks 规则 | 有可提交内容或可 Amend；复用提交用例 |
| 提交所有… | 预览将加入索引的已跟踪改动，再进入提交流程；不得静默包含未跟踪文件 | 有可提交的已跟踪改动；确认暂存范围 |
| 提交选中项… | 只处理当前可见文件选择，预览实际路径集合 | 选择有效且无冲突；选择变化时重新校验 |
| 重置… | 选择目标与 soft/mixed/hard 模式；hard 明确列出会丢弃的已跟踪改动并二次确认 | 仓库有 HEAD 且无其他写任务；高风险 |
| 隐藏变更… | 参考语义固定前保持待实现，不能擅自映射为 stash 或忽略文件 | 未确定，不得执行 |
| 推送… | 打开现有多分支推送面板；显示远端、refspec、ahead 和标签范围，不默认 force | 有安全推送目标；支持取消和结果核验 |
| 拉取… | 打开现有 Pull 配置，展示远端、分支和合并/变基策略 | 当前分支有可选目标；最终由 Git 校验改动冲突 |
| 抓取… | 打开现有 Fetch 配置，支持 all/prune/tags 和取消 | 至少一个远端；不修改 worktree/index |
| 更新 | 语义冻结前不得默认为 Pull、Fetch 或子模块更新 | 未确定，不得执行 |

### 4.3 引用与高级仓库能力

| 菜单项 | 行为契约 | 启用条件与风险 |
| --- | --- | --- |
| 检出… | 选择本地/远端分支或提交，展示 detached HEAD 结果；不覆盖用户改动 | 目标有效且无冲突操作；Git 决定能否安全切换 |
| 分支… | 复用现有分支管理面板 | 仓库有可作为起点的提交 |
| 合并… | 选择明确目标并显示目标/当前分支；冲突视为暂停状态 | 附着 HEAD、目标有效、无其他写任务 |
| 标签… | 复用现有标签面板，明确本地创建及可选远端推送的部分成功结果 | 有目标提交 |
| 贮藏… | 复用现有贮藏工作流，不默认包含未跟踪文件 | 有可安全保存的已跟踪改动且无冲突 |
| 交互式变基… | 复用 todo 编辑器和 Continue/Abort；操作前要求干净工作区 | 有合法基点、附着 HEAD、无其他写任务 |
| 添加远程仓库… | 展示名称和脱敏 URL，校验重名；只写当前仓库配置 | 仓库已加载；明确确认 |
| 添加子模块… | 预览 URL、目标目录和父仓库改动，禁止覆盖已有路径 | 后续平台能力；网络与工作区写入 |
| 添加/链接子树… | 在确定 add/link 语义和可恢复路径后实现 | 后续高级能力 |
| Git LFS | 只在检测到可用 Git LFS 后开放对应管理入口 | 后续扩展；不能伪造 LFS 状态 |
| Git Flow | 本项目只支持 Git，不显示或实现 hg flow；Git Flow 是否进入正式范围仍需产品确认 | 后续决策项 |
| 显示远程服务器 | 仅打开经过脱敏和协议白名单校验的仓库网页地址 | 能可靠解析受支持的 HTTP(S) 远端 |
| 创建拉取请求… | 先确认远端托管平台、目标/源分支和推送状态，再调用受支持平台集成 | 后续托管平台能力；不得猜测目标分支 |

## 5. “动作”菜单规格

“动作”菜单作用于当前页面选择。Flutter 是文件、提交、冲突和操作状态的唯一选择来源；AppKit
只负责系统级打开、Finder、Quick Look 和终端适配。

### 5.1 查看与外部工具

| 菜单项 | 行为契约 | 启用条件与执行层 |
| --- | --- | --- |
| 打开 | 用系统默认应用打开单个现存文件；目录按 Finder 处理 | 单个本地路径且仍存在；AppKit 平台服务 |
| 在 Finder 中显示 | 定位选中文件；无文件选择时定位仓库根目录 | 前台工作区有可解析路径；AppKit |
| 在终端中打开 | 在用户配置的终端打开仓库或选中文件所在目录，不拼接 shell 命令 | 路径存在；平台端使用结构化参数 |
| 快速查看 | 对当前文件选择调用 macOS Quick Look | 至少一个现存本地文件；AppKit |
| 外部差异比对 | 通过配置的 Diff 工具打开明确的左右版本；无配置时引导设置 | 单文件且两侧内容可解析；平台适配层 |
| 查看选中的修改日志… | 打开以所选路径为过滤条件的历史视图 | 有 tracked 路径；Flutter history 用例 |
| 审查选定项目 | 进入内置 Diff/审查视图，不自动暂存或提交 | 有可审查的文件或提交选择 |

### 5.2 补丁

| 菜单项 | 行为契约 | 启用条件与风险 |
| --- | --- | --- |
| 创建补丁… | 已交付；复用历史 Graph、文件、Diff 和详情，多选提交按从旧到新导出，现有文件不覆盖 | 仓库含可导出提交；文件输出失败保持原文件 |
| 应用补丁… | 已交付；支持试运行和 strip 选择，区分默认 `-p1` 与显式值 | 仓库已加载且无冲突任务；失败后刷新状态 |

### 5.3 索引、文件与提交

| 菜单项 | 行为契约 | 启用条件与风险 |
| --- | --- | --- |
| 添加到索引 | 暂存当前选择，路径使用 literal pathspec 和 `--` | 选择含可暂存改动；复用 stage 用例 |
| 移除 | 预览删除路径和 tracked 状态；tracked 文件与未跟踪文件采用不同确认和 Git/文件路径 | 有可移除选择；高风险，不允许无确认批量删除 |
| 从索引中取消暂存 | 取消暂存当前选择，不丢弃 worktree 内容 | 选择含 staged 改动 |
| 添加/移除 | 明确展示将暂存的新增、修改和删除集合后执行 | 存在对应 tracked 变化；不得吞入隐藏选择 |
| 停止追踪 | 从 index 移除但保留工作区文件，并解释后续仍可能被重新添加 | 选择为 tracked 路径；明确确认 |
| 忽略… | 选择写入位置和规则，预览 `.gitignore` 变更；已跟踪文件不会因忽略而停止追踪 | 有路径选择且 ignore 文件可安全编辑 |
| 提交… | 以当前选择预填提交面板，不绕过现有提交校验和 hooks | 选择可提交且无冲突 |
| 重置… | 对选择执行安全的 index/worktree 重置选项，默认不丢弃工作区内容 | 有适用选择；丢弃内容时明确确认 |
| 重置到提交… | 展示提交目标和 soft/mixed/hard 影响，hard 二次确认 | 当前选择为提交且无其他写任务 |
| 复制… | 复制文件到用户选择的目标，预览冲突和覆盖策略 | 有本地文件选择；默认不覆盖 |
| 移动… | 移动/重命名路径并刷新 Git 状态，预览覆盖与跨卷行为 | 有本地文件选择；默认不覆盖 |

### 5.4 进行中操作、冲突与扩展

| 菜单项 | 行为契约 | 启用条件与风险 |
| --- | --- | --- |
| 继续 | 根据 Git 检测到的 merge/rebase/cherry-pick/revert 状态调用对应 Continue | 恰有一个受支持操作暂停且冲突已解决 |
| 终止 | 展示将恢复/保留的状态后调用对应 Abort | 恰有一个可中止操作；明确确认 |
| 使用我的版本 / 他们的版本 | 显示实际 stage/分支含义，避免在 rebase 中用“我的/他们的”造成误解；保存后仍需用户确认标记解决 | 选择为单个可处理文本冲突；高风险 |
| 自定义操作 | 使用独立信任模型、结构化 argv、工作目录和环境白名单；默认关闭且不经 shell | 后续扩展；配置和每次执行均显示影响 |

## 6. “窗口”菜单规格

窗口菜单面向当前 key app window。它与仓库菜单不同：首页也可以成为合法窗口目标。系统提供的
标准 selector 应优先复用 AppKit 行为，避免 Flutter 模拟窗口几何和标签页状态。

| 菜单项 | 行为契约 | 启用条件与执行层 |
| --- | --- | --- |
| 最小化 / 缩放 | 保持系统标准行为 | 当前 key window 支持；AppKit，已交付 |
| 填充 | 将窗口调整到当前屏幕 `visibleFrame`，保留菜单栏和 Dock 安全区 | key window 可调整大小；AppKit |
| 居中 | 在当前屏幕可见区域居中，不改变窗口内容尺寸 | key window 存在；AppKit |
| 移动与调整大小：靠左/靠右 | 在当前屏幕可见区域平铺，不越界且遵守窗口最小尺寸 | 可调整大小且屏幕空间足够；AppKit |
| 全屏平铺：左侧/右侧 | 使用受当前 macOS 版本支持的系统全屏平铺能力；不支持时禁用 | 系统能力可用；AppKit |
| 从组中移除窗口 | 将当前原生标签页移出标签组，保留其 Engine 和仓库会话 | 当前窗口属于多标签组；AppKit |
| 移动到显示器 | 动态列出当前在线显示器，并把窗口约束在目标 `visibleFrame` | 至少两个显示器；AppKit |
| 显示仓库浏览器 | 显示/恢复唯一首页窗口 | 应用运行中；AppKit，已交付 |
| 显示托管在远端的仓库 | 打开受支持托管平台的仓库浏览器，不复用本地仓库首页伪造结果 | 配置受支持账户；后续平台集成 |
| 显示上一个/下一个标签页 | 在当前原生标签组内切换 | 标签组至少两个窗口；AppKit |
| 将标签页移到新窗口 | 从标签组移出当前标签，Engine 生命周期保持不变 | 当前窗口属于标签组；AppKit |
| 合并所有窗口 | 将两个及以上 workspace 合并为原生标签组，首页不参与 | 至少两个存活 workspace；AppKit，已交付 |
| 显示标签页栏 / 显示所有标签页 | 使用 AppKit 标准标签页能力，标题应随显示状态切换 | 当前窗口支持标签页；AppKit |
| 置前全部窗口 / 系统窗口列表 | 保持 macOS 标准窗口菜单行为 | AppKit，已交付 |

窗口移动、平铺和跨显示器操作必须覆盖不同缩放比例、Dock 位置、显示器热插拔、全屏 Space、最小
窗口尺寸和屏幕断开后的恢复。任何几何计算都以目标屏幕 `visibleFrame` 为边界。

## 7. 职责分工

| 层级 | 负责 | 不负责 |
| --- | --- | --- |
| XIB / `NSMenu` | 菜单层级、分隔、标准快捷键、系统菜单注册 | Git 状态、业务选择、命令参数 |
| AppDelegate / WindowCoordinator | key window、窗口 selector、每窗状态快照、MethodChannel 投递 | 猜测后台仓库、拼接 Git 命令 |
| DesktopWindowBridge | 每个 Engine 的类型化事件传递和关闭失效 | 保存跨窗口业务状态 |
| Flutter Presentation | 当前选择、对话框、进度和错误反馈 | 直接启动 Git CLI |
| Application / RepositorySession | 前置校验、操作队列、刷新和结果协调 | 伪造 Git 结果 |
| GitRunner / platform adapters | 结构化 Git argv、取消、脱敏；Finder/终端/Quick Look 等系统调用 | 决定产品交互和隐式扩大作用范围 |

正式 action ID 应使用稳定、可测试的语义名称，例如 `repository.refresh`、`action.stageSelected`、
`window.moveToDisplay`。涉及选中对象时只传递不可变标识或在 Flutter 内重新读取当前选择，不把展示
标题作为协议字段。

## 8. Git 安全矩阵

| 风险级别 | 代表动作 | 最低保护 |
| --- | --- | --- |
| 只读 | 详情、刷新、Finder、Quick Look、历史 | key workspace/路径校验、可取消、错误可见 |
| 远端只读或引用更新 | 远端状态、Fetch | 脱敏目标、进度/取消、结束后刷新 |
| index/worktree 写入 | stage、unstage、ignore、应用补丁 | 精确路径预览、literal pathspec、失败后刷新 |
| 引用/历史写入 | commit、merge、rebase、tag、stash、pull、push | 目标与范围确认、操作互斥、冲突恢复路径 |
| 破坏性 | hard reset、文件移除、停止追踪、Abort、冲突选边 | 安全默认、明确影响、额外确认、禁止静默批量执行 |
| 外部执行 | 终端、外部 Diff、自定义操作、托管平台 | 参数结构化、环境/协议白名单、凭据脱敏、默认不经 shell |

任何菜单实现都不得自动执行 `reset --hard`、`clean`、强制推送、删除未合并分支或删除未知
`index.lock`。确需开放时，必须满足项目级危险操作约束并有独立测试。

## 9. 快捷键与可访问性

- 优先保留 macOS 标准快捷键；新增快捷键前检查系统菜单和现有 Flutter Shortcuts 冲突。
- 同一动作无论来自菜单、工具栏、右键菜单还是快捷键，都调用同一应用层用例和安全校验。
- 菜单标题、禁用状态和快捷键随 key window 切换及时更新，不泄漏其他 workspace 的状态。
- 中英文菜单使用同一 action ID。省略号只用于点击后还需输入或确认的动作。
- 菜单必须支持键盘导航、VoiceOver 朗读和 200% 文字缩放；不能只靠颜色表达危险级别。

## 10. 测试与验收矩阵

每个从“待实现”转为已交付的菜单项，至少覆盖：

| 范围 | 必测场景 |
| --- | --- |

1. Swift 单元测试覆盖 key window 解析、菜单校验、窗口几何和 per-window 快照失效。

3. 临时真实 Git 仓库覆盖准确 argv、index/refs/worktree 结果和失败后刷新。

## 11. 已知限制与待决语义

以下内容当前仍是产品定义问题，未确认前必须保持“待实现”，不得由工程实现自行猜测：

- “刷新远程仓库状态”是否只做 `ls-remote` 探测，还是更新本地远端引用。
- “隐藏变更…”与现有“贮藏…”之间的准确差异。
- “更新”对应 Pull、Fetch、子模块更新还是组合工作流。
- Git-flow 是否进入支持范围；Mercurial 明确不在范围内，因此不实现 hg flow。
- 托管远端仓库、创建拉取请求所支持的平台、账户和认证方式。
- 自定义操作的信任模型、配置格式、环境变量和分发边界。
- 全屏平铺、窗口组和多显示器能力的最低 macOS 版本矩阵。

这些决策完成后，在本规范补充最终行为契约，并只在
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) 更新任务状态和交付顺序。
