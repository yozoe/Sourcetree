# Flutter Git 桌面客户端

这是一个以 Flutter 独立实现的桌面 Git 客户端项目。产品会对齐
Sourcetree 的核心工作流和信息密度，但不会复制其闭源代码、商标、
品牌素材或私有服务。

当前状态：**P1 MVP 垂直闭环进行中。** macOS 已采用“单进程、多原生窗口、每窗独立
Flutter Engine”：独立仓库首页与全部单仓库工作区共享一个应用生命周期和一个 Dock 图标。

当前版本可以打开、初始化和克隆仓库，展示工作区状态、最近提交、基础提交图和
单文件 Unified Diff。历史列表首次读取 100 条提交，并固定本次读取使用的本地分支与 HEAD 对象 ID；滚动到底部会基于同一引用快照继续追加更早的提交，即使外部 Git 客户端随后移动引用也不会重复或漏页。引用预览不会改变分页顺序；筛选后当前页没有匹配项时仍可继续加载，失败时可在列表末尾重试。列表使用紧凑的 24px 提交行和主题自适应图栏，保留图表、描述、提交、作者、日期表头，不显示行间分割线或常驻工具条；
Graph、描述、提交哈希、作者和日期列仍可从历史内容中的拖拽边界调整。Changes 区域支持
拖拽调整文件列表宽度，以及已暂存/未暂存文件区域的高度，窗口变窄时各列会按最小边界自动收缩。
游离 HEAD 位于多个分支的共同基点时，工作区节点与该基点共用最左车道，`main` 和其他分支在
右侧独立车道分叉并回连；最左工作区车道保持连续，尚未出现的侧分支不会提前绘制。分支标签边框
与其蓝/橙/红车道对应；分支会在共同基点所在行汇入，只有空位右侧仍活动的车道会同步向左补位。
每条车道仅在上一行确有连接时绘制圆点上方的竖线，分支首节点上方不会出现悬空线段。
主分支领先 upstream 时还会显示“超前 N 个版本”。
Changes 会展开未跟踪目录中的文件，不单独显示目录行；文件列表支持按住 Command
多选，右键菜单可复制路径、在 Finder 中定位，以及对选中的未跟踪文件执行暂存/取消暂存。
“移除”仅对全部选中的未跟踪项目开放，并会在确认后删除工作区文件；已跟踪改动不会被该入口删除。
选中历史提交后，会读取该提交的文件清单、增删行统计和所选文件
的 Unified Diff；合并提交按第一父提交显示改动。支持整文件暂存、提交、创建本地分支
以及安全 Fetch / Pull / Push。点击“拉取”会打开 Sourcetree 风格的配置框，可选择远端、远程
分支和合并策略：普通合并、立即提交、合并日志、强制生成合并提交，或用变基替代合并。
工具栏“推送”会显示当前分支相对 upstream 的领先提交数；只要当前分支有远端推送目标就保持可点击，
没有领先提交时会执行一次无改动检查，首次推送到已配置远端的分支仍可建立同名远端跟踪分支。
游离 HEAD 时如果仓库存在已配置远端的本地分支，推送会使用该分支的远端目标；否则仍需先切换到本地分支。
只要当前分支已配置 upstream，“拉取”按钮就可以打开配置框，即使工作区有未提交改动；确认后
会按所选远端和分支运行 Git，由 Git 判断当前改动是否会阻塞合并或变基。
工作区只要存在任意已暂存或未暂存改动，“提交”按钮即可打开提交面板；面板中可以勾选文件完成
暂存，也可以点击“已暂存文件/未暂存文件”分组标题的复选框批量切换整组文件，填写提交信息，并选择提交后立即推送。批量暂存使用一次 Git 操作，避免只完成部分文件。勾选“更正上一次提交”后会使用当前暂存内容执行
`git commit --amend`，保留 Git hooks。最终没有已暂存文件且未选择更正时，提交按钮保持禁用。
左侧“工作区”同时提供“文件状态”和“历史”入口：选中“文件状态”时，常规历史和提交详情分栏会隐藏，引用导航右侧完整展示已暂存/未暂存文件、所选文件 Diff 及底部提交信息入口；该入口会打开现有提交面板，不会在视图层直接执行 Git。“历史”保留提交图和下方改动面板；点击图顶端的 `Uncommitted changes` 仅选中该虚拟行并显示工作区改动，不会跳转到“文件状态”。
历史提交右键菜单提供检出、合并、从该提交创建分支、标签、复制 SHA-1、推送、变基（含交互式变基）、重置、提交回滚、创建补丁和遴选；附注标签的说明可留空，创建时不会打开外部编辑器。变基、回滚和遴选要求工作区干净且没有正在进行的 Git 操作；变基会提示本地历史改写影响。交互式变基提供可拖动排序的 todo 列表，支持 pick、edit、squash、fixup 和 drop；`reword` 在内置提交信息编辑器交付前不显示，避免无提示地保留原消息。冲突、edit 暂停、遴选或回滚暂停后均可继续或中止，且工具栏会持续保留遴选/回滚恢复入口。合并提交的回滚和遴选会要求选择主线父提交。重置提供 soft、mixed 和 hard 三种模式，其中 hard 必须额外确认会丢弃已跟踪的未提交改动。补丁导出不会修改仓库：可选择多个提交并按从旧到新的顺序合并为一个补丁，或存为目录内的独立文件；目标文件已存在时拒绝覆盖。标签名不符合 Git 引用规则时会直接说明名称格式，而不会误报为读取仓库失败。若标签已在本地创建但远端推送失败，界面会保留本地标签并明确提示该部分结果。

macOS 原生菜单栏新增“动作”菜单，其中“创建补丁…”直接复用仓库历史页的提交表格、Graph、引用标签、文件列表、Diff 和提交详情，可在同一窗口多选已加载提交并指定输出位置；“应用补丁…”可选择补丁文件，按默认 Git `-p1` 规则或明确指定剥离层级检查/应用到工作区。菜单同时保留打开、Finder/终端、快速查看、外部差异、暂存、移除、取消暂存、忽略、提交、重置、冲突处理、审查、复制和移动等 Sourcetree 风格入口；尚未在原生菜单实现的项均标注“待实现”，点击只显示提示且不执行 Git 操作。菜单仅对当前前台仓库窗口可用，不会作用于后台最近使用的仓库；补丁窗口支持拖动四边或四角调整大小，并限制在当前工作区可见边界内。补丁检查和应用完成后都会刷新真实 Git 工作区状态。

macOS 原生菜单栏还提供“仓库”菜单。“仓库详情…”会以可缩放的详情窗口展示当前仓库由 Git 实际读取的创建时间、最近提交、分支/标签/提交/已跟踪文件数量、作者提交统计、LFS 配置提示及工作区与 Git 数据目录的本地磁盘占用；空仓库使用“—”或零值而不会报错。其余仓库菜单项保留为带“待实现”文案的入口，点击仅提示待实现，不会执行 Git 写操作。详情读取和关闭均可取消，不会让主工作区进入加载或错误状态。

原生“窗口”菜单现以中文显示，保留系统最小化、缩放、当前窗口列表和“置前全部窗口”，并可直接打开仓库浏览器或合并全部工作区窗口。窗口平铺、显示器移动、窗口组、标签页切换及远端托管仓库入口按照 Sourcetree 的信息层级保留；尚未实现的项均标为“待实现”，在仓库浏览器或工作区位于前台时点击会显示原生提示，不会改变窗口或仓库状态。
历史提交右键的“合并”会精确合并所选提交，而非改为选择其他分支。提交行和详情中的标签使用独立的 tag 图标与橙色标签样式，不会与本地分支混淆。标签导航会保留 Git 返回的 tree/blob 等非提交目标，但不会尝试把它们加载为提交详情；标签删除若远端已成功而本地失败，会明确提示部分完成结果。
历史提交支持双击检出；确认框会说明分离 HEAD 的影响。工作区有未提交改动时仍由 Git 判断是否会覆盖文件，发生冲突则拒绝检出并保留原状态。检出后左侧引用和提交行都会显示临时 `HEAD` 标签。右键任一历史提交可打开“标签”面板：默认以该提交创建轻量标签，也可选择已加载的其他提交、在高级选项中创建带说明的附注标签，并可只将这个新标签推送到一个已配置远端。已读取的本地标签会显示在左侧“标签”分区并定位到目标提交；删除页可删除本地标签，或在明确确认后同时删除指定远端的同名标签。若本地创建成功但远端推送失败，应用会刷新并保留本地标签，不会伪造成功状态。
提交行中的主本地分支使用蓝色标签，其他本地分支使用对应车道颜色；提交详情会沿用 HEAD、远端、主分支和其他本地分支的颜色语义；单个长分支名会优先完整显示，
包括 `codex/conflict-demo` 这类斜杠分支名。
提交 Graph 使用 Sourcetree 式连续活动车道：未变化的路径保持垂直；仅当分叉新增车道或路径结束释放空位时，受影响位置右侧的活动车道才以一组短斜线同步补位。这既避免每行无条件重排，也不会留下贯穿长历史的空洞和长横线。图栏最多展示 8 条物理车道，第九条及更右侧的逻辑路径会折叠进第八条溢出车道，提交节点始终可见且不会越过图栏覆盖提交描述；活动车道收缩后恢复各自独立显示。当前 HEAD 谱系固定使用主蓝色车道，复杂的游离 HEAD 历史也会保留完整的汇合节点和连线。节点、连线、提交标签和左侧分支导航图标统一复用实际车道颜色。主本地分支为蓝色，HEAD 和远端引用为橙色，其他本地分支会按其车道在橙、红、绿、紫、青等多色调色板中区分；历史搜索只隐藏不匹配的行，不重新计算剩余行的 Graph 拓扑。
左侧引用导航会按已配置远端分组展示远端跟踪引用：例如 `origin` 可展开为 Git 实际返回的
`HEAD` 符号引用和 `main` 等分支。右键远端名称可直接从该远端获取，或打开默认选中该远端的
拉取、推送配置；“移除远端”会明确确认，并且只移除本地 Git 配置与跟踪引用，不删除远端仓库或
远端分支。点击非符号远端分支会在工作区干净时创建对应的本地跟踪分支并切换；它不会隐式 Fetch，
需先刷新远端引用。
本地分支名中的 `/` 会显示为可展开的目录层级，例如 `codex/conflict-demo` 显示为
`codex` 目录下的 `conflict-demo`；远端引用显示为远端名称下的相对分支路径，便于确认来源。
左侧工作区、分支、远端、标签与贮藏均支持右键菜单：工作区可获取或刷新，当前分支可获取、
拉取或推送，其他本地分支可切换或合并到当前分支，远端分支可创建本地跟踪分支并切换。普通未提交改动
仍可随本地分支切换保留；若存在未解决冲突、upstream/ahead 状态不满足条件或正在运行操作，菜单会禁用不可安全执行的项目，
工具栏“分支”会打开带切换动画的分支管理面板：可从当前 HEAD 或已加载的任意提交创建本地分支，选择是否立即检出；删除页可勾选本地或远端分支，并显示类型列。默认仅安全删除已合并的本地分支；勾选“忽略合并状态强行删除”后会在明确确认下使用 Git 强制删除，远端勾选会请求对应远端删除并受其权限与保护规则限制。
工具栏“推送”会打开分支映射面板，可选择任一已配置远端、勾选多个本地分支，并为每项手动输入或从已获取引用中选择远程分支；面板还可设置上游跟踪及推送所有标签。所有推送均使用 Git 的非强制模式，完成或失败后重新读取仓库状态。
工具栏“抓取”会打开简洁的选项面板，默认抓取全部已配置远端；可按需清理已从远端删除的跟踪分支，并抓取和存储全部标签。操作可取消，结束后会刷新 Git 引用状态。
其他可能覆盖改动的情况交由不带强制参数的 Git 拒绝并保留原状态。
工具栏“贮藏”和左侧“已贮藏”入口（始终显示在远端之后）可创建真实 Git 贮藏：存在可保存的已跟踪改动、
没有冲突且没有进行中的 Git 操作时，点击任一入口会打开紧凑的创建弹框，可填写说明并选择保留暂存区；
该入口可重复打开，其他状态会明确禁用。左侧“已贮藏”会固定展开真实 Git 贮藏列表，每条记录显示 Git 提供的
分支和说明；点击记录会隐藏常规历史与详情分栏，在引用导航右侧完整预览其中的文件和 Diff，右键菜单可查看列表、恢复并保留、恢复并弹出和在明确确认后删除。
默认不会包含未跟踪文件。恢复仅在
工作区干净时执行，并使用 `--index` 尝试还原暂存区；恢复发生冲突时会保留贮藏、刷新冲突状态，
不静默删除任何改动。未跟踪的嵌套 Git 仓库无法由父仓库贮藏；应用会拒绝创建空贮藏，需在该嵌套
仓库中单独处理。
本地分支右键菜单还可从所选分支创建新分支、重命名分支；这些引用操作不会改写工作区文件，因此存在普通已暂存、未暂存或未跟踪改动时仍可使用。非当前分支的删除弹窗会显示目标分支，并提供“强制删除”和“删除远程分支”选项；默认仍使用 Git 的安全删除模式，强制删除及上游远端删除必须由用户明确勾选。重命名不会覆盖已有分支，冲突或仓库操作进行中仍禁用这些入口。
工具栏支持将一个本地分支合并到当前分支；来源有新增提交时会创建显式合并提交。合并冲突会被
读取并展示。在冲突文件上点击右键，可通过“解决冲突 → 打开内部 Diff 工具”左右对比
“我的版本”与“他们的版本”，差异行会高亮；可选用任意一侧、继续编辑下方合并结果，
然后保存并暂存为已解决。二进制、非 UTF-8 或超过内部读取上限的冲突文件仅供查看，避免误写。
变基冲突会保留为“变基进行中”状态，并弹出“继续变基 / 放弃变基 / 取消”提示；用户也可在工具栏继续或中止变基。合并冲突仍由用户处理
冲突并确认合并提交。远端 URL 在显示前会脱敏，避免把 URL 中的用户名、Token 或密码展示到界面。
合并目标会固定解析为本地分支引用，即使仓库存在同名 Tag 也不会合并错误对象。
macOS bundle 的用户主动远端操作可使用单次受控 AskPass；发布签名、真实私有远端和
系统凭据兼容性仍在验证中。

macOS 启动后首先显示独立的仓库首页。之后从 Dock 重新激活应用时会恢复最后位于最前方的首页或仓库工作区，不会总是跳回首页。首页保存并恢复成功打开过的仓库路径，支持筛选、
打开、克隆和初始化；已被移动、删除或不再可读的路径会自动跳过。仓库根目录中存在可读取的
`icon.png` 时，首页会以该图片显示圆形仓库图标；图片缺失、不可读或无效时保留默认 Git 图标。每个仓库条目右侧同时显示 Git 读取到的当前分支和未提交文件数；游离 HEAD 与尚未首次提交的分支会明确标注。工作区完成导致 Git 状态变化的操作后会通知首页刷新对应摘要。点击仓库会创建独立的
单仓库工作区窗口，同一路径只允许存在一个窗口；再次点击会把已有窗口带到最前方，连续点击
会合并为同一次启动请求。工作区中的“打开仓库”也使用这一窗口入口。默认每个仓库保持独立窗口；从系统“窗口”菜单选择“合并所有窗口”后，所有已打开工作区会合并为标题栏下方的原生 macOS 标签页，标签显示仓库名。标签仍各自拥有独立 Flutter Engine 和 Git 状态，关闭一个标签只关闭该仓库工作区。
首页支持将 Finder 中的一个或多个目录拖入窗口；应用只加入能由 Git 识别的仓库根目录，重复或非仓库目录会被跳过。仓库仍按父目录分组，可在同一目录组内拖动手柄调整显示顺序；筛选状态下不提供排序，以免误调整隐藏条目。首页的“筛选仓库”输入框会在其紧凑工具栏高度内垂直居中文字和搜索图标。

工作区加载仓库成功后会立即通知首页更新仓库清单。首页按顺序处理多个窗口的回传，避免并发
打开时丢失仓库记录。窗口不会保存 Git 凭据、操作记录或工作区内容。已实现的窗口架构与调试边界
详见 [macOS 窗口模型](docs/MACOS_WINDOW_MODEL.md)。

## 代码文档

`lib/` 的每个具名方法均在声明处提供中英双语 DartDoc，说明其职责而不复述实现细节。
其中私有方法用于解释状态边界、Git 命令解析或 Widget 生命周期；公开方法同时说明调用方
可依赖的行为。禁止使用“处理某方法相关逻辑”这类占位说明；新增或修改方法时，必须同步更新
双语注释及相关测试。

## UI 基础库

桌面界面通过固定 Git 提交依赖接入 `yeknom_ui_kit` 的 `lib/`，并使用
`YeknomWorkbenchTheme`。首页与所有工作区共享系统/浅色/深色模式和主题色偏好，修改后会
同步到其他已打开窗口。该依赖只提供 Flutter Material 的主题、语义颜色和可复用控件；Git、
状态管理、文件访问和业务文案仍保留在本项目中。固定提交使本项目在全新克隆和 CI 环境中
无需特定本地目录结构即可复现构建。

## 运行

```sh
flutter pub get
flutter run -d macos
```

验证命令：

```sh
flutter analyze
flutter test
flutter test integration_test/macos_core_workflow_test.dart -d macos
flutter build macos --debug
```

## 安装到 Applications

在项目根目录运行：

```sh
./install_macos.sh
```

脚本会构建 Release app，先请求唯一的已安装应用进程退出，再将新版本暂存到
`/Applications` 内的隐藏临时目录。替换或 LaunchServices 注册失败时会恢复旧版本；成功后
清理暂存目录并启动 `/Applications/Git Desktop.app`。脚本不会留下重复 app bundle、关闭
Gatekeeper 或修改任何 macOS 安全设置。
