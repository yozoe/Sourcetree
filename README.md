# Flutter Git 桌面客户端

> 文档说明：本文以中文为主，并在关键能力、限制和验证入口处提供英文对应说明。
> Documentation: This README is Chinese-first, with English counterparts for key capabilities,
> limitations, and verification entry points.

这是一个以 Flutter 独立实现的桌面 Git 客户端项目。产品会对齐
Sourcetree 的核心工作流和信息密度，但不会复制其闭源代码、商标、
品牌素材或私有服务。

当前状态：**P1 MVP 垂直闭环进行中。** macOS 已采用“单进程、多原生窗口、每窗独立
Flutter Engine”：独立仓库首页与全部单仓库工作区共享一个应用生命周期和一个 Dock 图标。
首页仓库清单、工作区 Git 会话和每个 Engine 的主题偏好均有独立的 Riverpod 状态边界：首页恢复时
只识别仓库并读取摘要，不读取工作区历史或 Diff；主题仍通过原子偏好文件和原生协调器在不同 Engine 间同步。
原生“仓库”“动作”“窗口”菜单的已交付入口均使用独立语义 action ID，并只路由当前 key workspace。
菜单 capability 快照按 Flutter Engine 隔离，带有单调递增 generation；窗口切换、选择或 Git 能力变化、
后台任务结束、窗口关闭和 Engine 销毁后，旧快照不会继续启用入口，迟到的旧 generation 也不会覆盖最新状态。
真正未交付的入口继续直接显示“（待实现）”，点击只显示提示，不执行 Git、文件或窗口操作。
高风险写操作的状态栏日志会区分成功、失败、取消、部分完成和结果不确定；M3 异常矩阵已覆盖所有已交付的 Git、文件、Diff 和冲突恢复入口，并由 554 项 Flutter 测试验证（1 项受控真实远端测试按环境跳过）；批量引用删除会保留
已完成与失败项的实际结果，Push 在异常或取消后无法核验远端时会要求刷新确认，不会盲目重试。
Fetch 全部远端时若部分远端已更新而后续远端失败，日志会标记结果不确定并要求刷新核对各远端引用；
Pull、Push 或引用删除在写入完成但本地状态刷新失败时也不会伪造普通成功。
Fetch、Pull、Push 和贮藏的运行中取消会终止对应 Git 进程并保留取消结果；写入完成但刷新失败的边界由可重复测试钩子验证为“结果不确定”。
合并、变基、遴选和回滚在写入后刷新失败时同样保留“结果不确定”，并要求用户刷新确认真实 Git 状态。
合并及其他冲突恢复操作会把冲突保留在 Git 中，并在操作日志中记录失败原因和继续/跳过当前提交/中止恢复入口。
Reset、停止追踪和历史文件恢复等文件写操作也会进入操作日志；仓库初始化也会记录引用操作结果。写入后刷新失败时显示结果不确定，并保留手动刷新入口。
整文件暂存和取消暂存也记录为文件操作；Git 已完成而工作区刷新失败时会保留结果不确定状态。
忽略规则、工作区复制、移动和删除也保留逐项结果；部分完成或刷新失败时不会伪造整体成功。
Diff 区块暂存、取消暂存和放弃也使用相同的文件操作结果记录，Git 拒绝过期补丁时保留失败原因；写入后刷新失败会明确记录结果不确定。
远端配置和本地分支创建会分别显示为“远端配置”和“引用操作”；写入后刷新失败会要求刷新确认，不会伪造完成状态。
标签创建或远端/本地删除失败时会保留已完成的一侧，并在引用操作日志中标记部分完成；批量本地标签读取、删除和推送也绑定到窗口级取消屏障，标签分区运行期间提供“取消标签操作”按钮，关闭窗口或取消时不会继续启动后续标签操作。
本地分支创建、切换、重命名、远端分支检出和提交检出也会记录引用操作；写入完成但刷新失败时要求刷新确认。
Clone 在启动前或 Git 已开始后取消都会明确区分无残留与保留部分 Git 数据；其他远端操作的取消会保留当前仓库状态并显示可刷新确认的结果。
冲突文件选择 ours/theirs、使用共同基线（撤销双方改动）、按冲突标记逐段选择一侧、标记已解决或保存内部合并结果也会记录文件操作状态；共同基线按钮只在有 Git stage 1 时显示，逐段入口只解析完整的标准 Git 冲突标记，冲突未消失时保留继续/跳过当前提交/中止恢复入口。

历史文件右键菜单的“外部差异比对”会按第一父提交读取最多 16 MB 的前后原始 blob，并在 Apple
FileMerge 已安装时打开两个权限受限的临时快照；新增或删除文件缺失的一侧为空内容，关闭工作区时
清理快照。该入口不执行仓库配置中的 external diff 或 textconv；仓库详情已提供应用级只读外部
Diff 配置面板，启用且信任仓库后，工作区/历史文件及原生 macOS“动作”菜单的外部差异入口
会使用该 argv 工具；未启用时继续使用 Apple FileMerge。
应用层外部 Diff 生命周期已固定为非 Shell argv、受信任仓库与显式启用双门槛、单侧
16 MB 快照上限，以及取消/关闭时终止进程并清理私有快照；配置文件采用原子替换，损坏或不安全记录会回退为空配置，Merge 写回不会被保存；Engine 级配置状态会顺序写入、显示保存失败并在关闭前等待写入完成。这些配置仍未暴露为用户菜单。
工作区单文件“外部差异比对”同样使用 FileMerge：已暂存行比较 `HEAD` 与 index，未暂存行比较
index 与当前工作树，避免把两个层级的改动混在一起；未跟踪、冲突和子模块仍不提供外部 Diff，
但子模块改动行仅保留 Git 返回的既有只读状态兼容显示，不会触发递归更新或其他嵌套仓库写操作，也不新增 Submodule 管理入口。
工作区文件右键菜单的“创建补丁…”会把当前选择中的已跟踪改动相对 `HEAD` 导出为一个二进制安全
补丁；暂存与未暂存内容合并反映当前工作树结果，重命名同时包含旧路径，目标文件绝不覆盖。未跟踪、
冲突和非 UTF-8 路径暂不支持，并在菜单中直接标注“（待实现）”；无提交仓库会以 Git 空树为基线。

macOS 应用图标已更新为原创的亮蓝色分支提交图标：中央以较大比例的白色主提交、短主干和侧分支构成
树形标记，外围保留透明安全边距以适配 Finder 与 Dock。图标只借鉴桌面 Git 客户端的公开信息语义，
不使用 Sourcetree 的商标、Logo 或专有素材；图形源稿与渲染脚本位于 `design/render_icon.swift`。
`flutter run -d macos` 的运行时 Dock 视图会直接使用资源内的安全边距，不再叠加第二层缩进，
因此 Debug 应用与相邻的常规 macOS 图标保持相近的视觉尺寸。

当前版本可以打开、初始化和克隆仓库，展示工作区状态、最近提交、基础提交图和
单文件 Unified Diff。历史列表首次读取 100 条提交，并固定本次读取使用的本地分支与 HEAD 对象 ID；滚动到底部会基于同一引用快照继续追加更早的提交，即使外部 Git 客户端随后移动引用也不会重复或漏页。打开含历史的仓库时会默认选中最新提交，并显示其详情和首个可预览文件的差异；无提交或无文件改动时保留对应空状态。引用预览不会改变分页顺序；筛选后当前页没有匹配项时仍可继续加载，失败时可在列表末尾重试。搜索框支持真实 Git 查询条件 `author:`、`committer:`、`path:`、`after:` 和 `before:`（可组合，日期使用 ISO 格式），未带条件的文字继续在已加载提交的标题、正文、作者和对象 ID 上快速筛选；条件查询会从固定引用快照重新分页，查询切换、仓库切换和窗口关闭会取消过期读取。列表使用紧凑的 24px 提交行和主题自适应图栏，保留图表、描述、提交、作者、日期表头；日期表头和内容均左对齐，不显示行间分割线或常驻工具条；
在嵌入式窄窗口的单栏布局中，选择左侧“文件状态”会同步切换到工作区文件面板，而选择“历史”会恢复提交图；不会出现引用已选中但仍停留在历史面板的状态。
本地分支右键菜单新增只读“查看引用日志”，按 Git 实际返回的 reflog 记录展示分支移动、提交消息、选择器、对象 ID 和时间；支持按选择器、对象 ID 或消息筛选，并可点击记录定位到对应提交；读取可取消，不执行检出、重置或其他写操作，分支删除或仓库切换不会把旧记录写回当前窗口。
历史文件的只读修改日志窗口新增 Blame 入口；它对当前工作树路径执行 `git blame --line-porcelain`，按行显示责任提交、作者、短对象 ID、源码行和提交摘要。Blame 读取支持取消，不会修改索引、工作区或当前历史选择；已删除或无法安全表示的路径继续显示“（待实现）”并禁用。
当前工作区文件右键菜单也可直接打开同一只读 Blame 视图；仅对单个、仍存在且已跟踪的 UTF-8 文件开放，未跟踪、删除、冲突或多选时显示“Blame（待实现）”并禁用，执行前会重新校验选择。
仓库顶部只保留一条 Git 操作栏，不重复显示 Flutter 仓库标签条；每个操作均以图标在上、标签在下的紧凑按钮呈现，主题设置位于该操作栏末端，并会在无仓库、加载或错误状态下保留在右上角。多仓库切换继续通过独立窗口或 macOS 合并窗口的原生标签完成。紧凑工具栏、状态栏、首页工具栏、历史、文件、Diff 和冲突对比行会随系统文字缩放增加高度，不再在 1.6 倍封顶；极端缩放下信息密度会相应降低。
首次读取仓库且尚无可用数据时，工作区会按当前窗口宽度显示与正式工作台一致的三栏或两栏骨架屏，同时保留真实的读取说明、仓库路径和可用的取消克隆入口。Flutter 工作区保留低于 760px 的单栏布局供嵌入场景使用，但当前 macOS 原生窗口最小宽度为 900px，因此正常窗口缩放最低会停在两栏。已有仓库数据的局部刷新，以及 Fetch、Pull、Push 和贮藏等后台任务，均保留当前工作台内容并只显示顶部进度，因此任务进行中仍可浏览和切换当前查看的引用；任务运行、仓库加载或历史写操作期间不能再触发刷新，会改变仓库的冲突写操作仍按安全边界禁用。
Graph、描述、提交哈希、作者和日期列仍可从历史内容中的拖拽边界调整。Changes 区域支持
拖拽调整文件列表宽度；历史提交的“提交改动”区域也支持拖拽调整文件列表与 Diff 的分栏宽度；
已暂存/未暂存文件区域的高度同样可调整，窗口变窄时各列会按最小边界自动收缩。
游离 HEAD 位于多个分支的共同基点时，工作区节点与该基点共用最左车道，`main` 和其他分支在
右侧独立车道分叉并回连；最左工作区车道保持连续，尚未出现的侧分支不会提前绘制。分支标签边框
与其蓝/橙/红车道对应；分支会在共同基点所在行汇入，只有空位右侧仍活动的车道会同步向左补位。
每条车道仅在上一行确有连接时绘制圆点上方的竖线，分支首节点上方不会出现悬空线段。
主分支领先 upstream 时还会显示“超前 N 个版本”。
Changes 会展开未跟踪目录中的文件，不单独显示目录行；文件列表支持按住 Command
多选，右键菜单可复制路径、在 Finder 中定位，以及对选中的未跟踪文件执行暂存/取消暂存。
暂存或取消暂存时，应用会保留当前文件列表和历史快照，只暂时禁用冲突的写操作；Git 完成后
仅重读工作区状态并原子更新分组，不再先清空列表或重新打开整个仓库。写入期间复选框保持
原有选中颜色但不可重复点击，“文件状态”标题会显示“正在更新”进度；真正不支持的操作才显示灰色禁用态。
在 `Uncommitted changes` 或“文件状态”执行刷新时也会保留当前入口和仍有效的文件选择；
刷新状态不会先选中最新提交再切回工作区。若原文件已不再有改动，旧选择和 Diff 会被清除。
工作区窗口会监听仓库文件和 Git 管理目录：编辑器或其他工具保存、创建、删除或重命名文件后，
事件会在短暂防抖后合并为一次 Git 状态读取，并同步刷新仍选中文件的 Diff；`HEAD`、引用或
合并/变基状态等元数据变化会重新读取仓库历史。应用自身 Git 写操作期间自动刷新会延后并合并，
窗口从后台恢复时还会完整校准状态、引用和历史。平台文件监听不可用或发生瞬时错误时，工具栏手动刷新
仍可使用；Git 确认状态未变化时会抑制重复界面更新，历史提交图也会复用未变化的拓扑；自动刷新
只负责触发读取，界面结果始终以 Git CLI 为准。自动刷新读取期间会保留当前提交改动、文件选择和
Diff 内容，待新状态与 Diff 读取完成后一次性替换；只有目标提交或文件确实失效时才清空对应区域，
避免编辑器保存时出现空白闪动。
暂存和未暂存列表中的“移除”均可用于删除所选文件的工作区副本；确认框会逐项列出路径并明确提示
未提交内容无法找回。该操作不直接修改 Git 索引或提交历史：已暂存内容仍保留在索引，删除后由
Git 真实状态显示新增的未暂存删除；未跟踪文件则从列表消失。确认后若所选行的暂存来源已经变化，
应用会拒绝使用过期选择并要求刷新重试。
批量移除会逐项反馈成功、已不存在和失败路径，避免部分文件已被不可逆删除时仍只显示统一失败；macOS 删除会从固定的工作区目录描述符逐级打开父目录并拒绝符号链接父级，目录无法安全递归时会作为失败项保留；其他平台当前同样拒绝递归目录删除，并在发布前重新验证父路径。
Git 路径不是有效 UTF-8 时，该入口禁用并直接标注“移除（待实现）”。
已暂存或未暂存的已跟踪修改、删除文件均在右键菜单中提供“重置…”：确认后会将选中路径的索引和工作区同时恢复到 `HEAD`，丢弃其已暂存和未暂存内容；尚未提交的新增文件不提供此入口，避免将恢复误解为删除文件。确认后会重新读取 Git 状态，并要求所选暂存区或工作区来源仍存在受支持的改动；若来源已经变化则拒绝覆盖并要求刷新。重置期间保留当前列表和入口，只原子更新 Git 工作区状态；若仍有其他工作区改动，提交图会始终选中 `Uncommitted changes`，不会先跳到下方最新提交再切回；若最后一个改动被重置，则直接选中最新提交。
“停止追踪”对普通已追踪改动和已暂存但尚未提交的新增文件开放；确认后会从 Git 索引移除所选路径并保留本地
文件。已有提交的文件会形成待提交的删除记录，已暂存新增文件则恢复为未追踪；提交前不会改变历史；未将路径加入 `.gitignore` 时，文件仍可能被
再次添加。即使同一文件同时有暂存和未暂存修改，确认后也会只从索引移除它而保留本地最新内容。停止追踪后，文件列表按 Git 原始状态分别展示已暂存的删除和同路径未暂存的未跟踪文件。
工作区文件右键菜单的“在终端中打开”“快速查看”“查看选中的修改日志…”和“审查选定的项目”
已接入与 macOS 原生“动作”菜单相同的应用层能力。终端只接受单个文件并打开其所在目录；Quick Look
和内置审查支持多选，文件历史只接受单个已跟踪路径。执行前会把菜单选择重新解析到最新 Git 视图，
系统文件动作还会由 AppKit 复核工作区归属、仓库边界和全部路径的存在性，失效多选不会部分执行。
同一菜单的“忽略…”会复用既有规则预览，可选择共享 `.gitignore` 或本机 `.git/info/exclude`，
并保留已跟踪文件不会因新增规则而自动停止追踪的边界。
“应用补丁…”也会打开既有补丁检查/应用面板，并继续在仓库忙碌或冲突恢复期间禁用；
“创建补丁…”已支持已跟踪文件的工作区选择；未跟踪、冲突、非 UTF-8 或无法通过最新状态复核的选择仍标注为“（待实现）”并保持禁用。
主 Diff 对常见源码扩展名提供轻量语法高亮；未知或不安全表示的文件继续显示原始等宽文本，不改变补丁内容、区块操作或复制结果。标题栏的空白比较菜单支持保留空白、忽略所有空白、忽略空白数量变化和忽略空白行；切换会重新读取真实 Git Diff，非默认模式只读展示并隐藏区块写操作，复制内容与当前筛选结果一致。
选中历史提交后，会读取该提交的文件清单、增删行统计和所选文件

左侧“工作区”同时提供“文件状态”和“历史”入口：选中“文件状态”时，常规历史和提交详情分栏会隐藏，引用导航右侧完整展示已暂存/未暂存文件、所选文件 Diff 及底部提交信息入口；该入口会打开现有提交面板，不会在视图层直接执行 Git。“历史”保留提交图和下方改动面板；点击图顶端的 `Uncommitted changes` 仅选中该虚拟行并显示工作区改动，不会跳转到“文件状态”。普通已跟踪文本文件的未暂存 Diff 区块同时提供“暂存区块”和“放弃区块”：前者只把该区块写入索引，后者确认后恢复到索引版本；已暂存 Diff 区块只显示“取消暂存区块”，从索引移除该区块并保留工作区内容。历史提交中的文本新增、修改和删除文件只会在会话就绪且没有其他任务时显示“回滚区块”，确认后把所选提交区块反向应用到当前工作区，形成新的未提交改动而不改写提交历史。工作区区块操作完成后会保留原入口并恢复同一路径仍有效的暂存或未暂存选择；已提交区块操作完成后继续选中原提交和文件。二进制、截断、冲突、重命名、复制以及同时改变已有文件模式（含 executable bit）的 Diff 不提供区块操作；若 Git 上下文已变化，补丁会被拒绝并要求刷新后重试。
历史提交的“提交改动”文件列表支持右键菜单，提供查看修改日志、审查、重置到提交、打开版本、Finder、复制路径、快速查看、外部差异比对和自定义操作入口。“查看选中的修改日志…”会打开独立的只读历史视图，以所选路径过滤已加载的本地分支历史，并用 Git `--follow` 追踪单文件重命名；每条记录都保留该提交中的实际路径，因此选择重命名前的提交也会显示该文件而非同次提交的其他文件。选择提交会显示实际读取的改动摘要和 Unified Diff，不会改写主工作区选择或仓库状态；关闭窗口或快速切换提交会取消已失效的 Git 读取。“审查选定的项目”会为该历史文件打开独立只读 Diff，不自动暂存、提交或改变主工作区选择。“重置到提交…”会在确认后把所选路径在目标提交中的版本同时写入 index 与 worktree，覆盖该路径当前已暂存和未暂存内容，但不移动 HEAD 或改写历史；目标提交中不存在该路径时会删除当前路径。执行前会重读 Git 状态和进行中操作，并要求确认框对应的提交与文件仍是当前已加载历史选择；detached HEAD 可以使用，冲突操作和其他任务期间保持禁用。“复制路径到剪贴板”会复制当前选择的仓库相对路径，并在写入系统剪贴板前复核提交和文件选择。“打开当前版本”“在 Finder 中显示”和“快速查看”会把同一路径的当前工作树文件交给 macOS 原生能力；原生层会再次检查请求属于当前工作区、路径没有越出仓库且文件仍然存在。“打开已选定版本”会从 Git 读取最多 16 MB 的原始 blob，拒绝截断结果，再由 AppKit 写入权限为 `0600` 的私有临时文件并用默认应用打开；临时目录权限为 `0700`，随工作区窗口关闭清理。删除记录在该提交中不存在文件内容，因此保持禁用。当前 Git 子进程与系统接口不能无损传递非 UTF-8 路径，因此这类文件的相关入口会禁用并直接标注“（待实现）”。其余尚未交付的入口也都会直接在标签中显示“（待实现）”，不能只依赖禁用态或点击后的提示；这些入口仅显示待实现提示，不执行 Git、文件或外部应用操作。
历史提交右键菜单提供检出、合并、从该提交创建分支、标签、复制 SHA-1、推送、变基（含交互式变基）、重置、提交回滚、创建补丁和遴选；附注标签的说明可留空，创建时不会打开外部编辑器。变基、回滚和遴选要求工作区干净且没有正在进行的 Git 操作；变基会提示本地历史改写影响。交互式变基提供可拖动排序的 todo 列表，支持 pick、edit、squash、fixup 和 drop；`reword` 在内置提交信息编辑器交付前不显示，避免无提示地保留原消息。冲突、edit 暂停、遴选或回滚暂停后均可继续、跳过当前提交或中止（合并暂停不提供跳过），且工具栏会持续保留遴选/回滚恢复入口。合并提交的回滚和遴选会要求选择主线父提交。重置提供 soft、mixed 和 hard 三种模式，其中 hard 必须额外确认会丢弃已跟踪的未提交改动。补丁导出不会修改仓库：可选择多个提交并按从旧到新的顺序合并为一个补丁，或存为目录内的独立文件；目标文件已存在时拒绝覆盖。标签名不符合 Git 引用规则时会直接说明名称格式，而不会误报为读取仓库失败。若标签已在本地创建但远端推送失败，界面会保留本地标签并明确提示该部分结果。

macOS 原生菜单栏新增“动作”菜单，其中“创建补丁…”直接复用仓库历史页的提交表格、Graph、引用标签、文件列表、Diff 和提交详情，可在同一窗口多选已加载提交并指定输出位置；“应用补丁…”可选择补丁文件，按默认 Git `-p1` 规则或明确指定剥离层级检查/应用到工作区。“打开”“在 Finder 中显示”“在终端中打开”和“快速查看”使用当前前台工作区的真实文件选择：路径由 Flutter 限制在工作树内，再由 AppKit 在执行时确认仍然存在；打开仅接受单个目标，Finder 与 Quick Look 支持多选且不会部分处理失效选择，无文件选择时 Finder 和终端使用仓库根目录，终端当前使用系统 Terminal。历史文件选择对应当前工作树中的同一路径，不存在时相关入口禁用。“查看选中的修改日志…”可对当前单个已跟踪工作区文件或历史提交文件打开同一只读文件历史视图；非 UTF-8、未跟踪或多文件选择保持禁用。“审查选定项目”会在独立双栏视图中展示当前工作区多选文件或历史文件的真实 Unified Diff；切换文件会取消过期读取，关闭窗口会取消未完成查询，且审查始终只读，不自动暂存或提交。“忽略…”会预览精确路径或扩展名规则，并可选择写入仓库根目录 `.gitignore` 或仅本机使用的 `.git/info/exclude`；执行前重读选择，既有规则不会重复写入，已跟踪文件不会被自动停止追踪；若目标文件在确认后被外部修改，则拒绝覆盖并保留外部内容。“添加到索引”和“从索引中取消暂存”会根据当前前台工作区的单选或多选文件集合动态启用，并复用文件列表现有的批量暂存切换与完成后状态刷新；混合选择中只处理与菜单方向一致的文件，过期、冲突、非 UTF-8 或任务占用期间的选择不会执行。“移除…”复用文件列表已有的批量删除确认：列出全部目标并警告未提交内容无法恢复，执行前重读 Git 状态，结果区分成功、已不存在和失败；任一路径无法安全表示或任务占用时入口禁用。“停止追踪”会随当前前台工作区选中的普通已跟踪文件、已暂存新增文件或历史提交文件动态启用；历史文件只提供路径，执行时仍会重新验证该路径在当前工作区的索引和本地文件状态，再复用确认和索引写入工作流；没有适用选择时保持禁用。检测到 merge、rebase、cherry-pick 或 revert 暂停时，“继续/跳过当前提交/中止”会动态显示具体操作名称；跳过仅适用于 rebase、cherry-pick 和 revert，未解决冲突会禁用继续，中止始终先解释恢复影响并确认。选中单个冲突文件时，“解决冲突”会按当前操作显示 Git stage 2/3 的真实来源，例如“当前分支/合并来源”或“变基目标基线/正在重放的提交”；不存在的 stage 会禁用，也可将当前工作区内容直接标记为已解决。继续、中止和冲突动作执行前都会刷新 Git 状态并复核操作与选择。菜单同时保留外部差异、提交和重置等 Sourcetree 风格入口；其余尚未在原生菜单实现的项均标注“待实现”，点击只显示提示且不执行 Git 操作。菜单仅对当前前台仓库窗口可用，不会作用于后台最近使用的仓库；补丁窗口支持拖动四边或四角调整大小，并限制在当前工作区可见边界内。补丁检查和应用完成后都会刷新真实 Git 工作区状态。

macOS 原生“动作 → 提交…”复用“提交选中项”流程，只处理当前 key workspace 的可见文件选择；提交前会重新读取 Git 状态并校验路径范围，其他已暂存文件保持不变。原生 Reset 也已按选择语义拆分：仓库菜单的“重置…”可从当前已加载历史选择目标提交；动作菜单的“重置到提交…”直接使用当前可见历史提交；两者默认 mixed，也可选择 soft 或 hard，hard 会列出将永久丢失改动的已跟踪路径并要求再次勾选确认。动作菜单的“重置…”只在全部工作区选择均为可恢复的已跟踪修改或删除时启用，经确认后将这些路径的 index 与 worktree 一起恢复到 `HEAD`。所有入口仅路由当前 key workspace，后台任务、冲突操作、游离 HEAD 和过期选择不会执行。

“复制…”允许为当前工作区的普通文件选择目标目录，先展示完整源与目标映射并检查同名冲突；执行前重新读取 Git 状态，复制过程支持窗口关闭取消，目标使用同目录临时文件和排他发布，任何已有条目都不会被覆盖。符号链接、目录和非 UTF-8 路径当前不复制。

“移动…”使用同一选择与预览边界，并在确认框说明同卷和跨卷行为：同卷文件通过排他原子重命名移动；跨卷文件先持久复制到目标，再仅在源路径仍指向原文件时删除。若源文件在复制期间变化或无法安全删除，会保留源文件和目标副本并反馈，不会为完成移动而覆盖目标或删除未知对象。符号链接、目录和非 UTF-8 路径当前不移动。

macOS 原生菜单栏还提供“仓库”菜单。“仓库详情…”会以可缩放的详情窗口展示当前仓库由 Git 实际读取的创建时间、最近提交、分支/标签/提交/已跟踪文件数量、作者提交统计、LFS 过滤器、本机 `git-lfs` 可用性及只读跟踪文件数量摘要；检测到过滤器但本机没有工具时显示“已配置 LFS（工具不可用）”，工具可用时显示“已配置 LFS（指针文件 N 个）”，不会触发下载或写操作；空仓库使用“—”或零值而不会报错。详情读取和关闭均可取消，不会让主工作区进入加载或错误状态。“Git Flow…”现支持 v1 Start 和单目标 Finish：Start 在干净、附着 HEAD 且无其他 Git 操作时，显式选择起点并预览后创建并检出本地 feature/release/hotfix 分支；Finish 在同样的安全门槛下显式选择一个本地目标分支，先检出目标再以 `merge --no-edit --no-ff` 合并当前 feature/release/hotfix 分支。两者都不推送、不删除分支或修改 upstream；Finish 冲突保留现有 Continue/Abort 恢复入口，检出成功但合并失败会保留目标分支和实际 Git 状态。Git LFS 写操作和其他托管能力仍保持“待实现”。尚未接入的仓库菜单项保留“待实现”标注和无副作用提示。

“仓库”菜单中的“刷新”“抓取…”“拉取…”“推送…”“提交…”“提交所有…”“提交选中项…”“检出…”“分支…”“合并…”“标签…”“贮藏…”“交互式变基…”和“添加远程仓库…”已接入当前 key workspace：刷新
重读仓库状态；抓取、拉取、推送、提交、检出、合并和标签复用应用内既有对话框与确认流程。“提交所有”会预览并提交全部已跟踪改动和已经暂存的文件，但不静默包含纯未跟踪文件；“提交选中项”只提交当前可见选择中各路径的完整工作区内容，不会带入其他已暂存文件，所选新文件会先进入 intent-to-add，若 hook 或提交失败则刷新并显示可能保留的状态。检出面板将非当前本地分支、已获取远端分支和已加载提交分组展示，支持搜索；远端分支会创建本地跟踪分支，提交目标会明确进入分离 HEAD。添加远端会校验名称重名并拒绝带内嵌凭据、查询参数或不受支持协议的地址，只修改当前仓库的本地 Git 配置，不会自动连接或抓取。合并会明确列出来源本地分支和当前目标分支，冲突会保留为可恢复的暂停状态；标签面板以当前选中提交为默认目标，没有历史选择时使用 HEAD，并保留本地成功但远端推送失败的部分结果。这些项由 Flutter 的当前
capability 快照动态启用，后台任务、暂停操作、没有远端/upstream、没有可推送或可提交改动，或
窗口切换后的过期快照都会禁用；远端分支检出需要干净工作区且不能与同名本地分支冲突，本地分支和提交检出则由 Git 判断现有改动能否安全携带；交互式变基仅在工作区干净、HEAD 未游离且选中了 HEAD 之前的可见提交时启用，并复用已有的 todo 编辑器；实际执行前仍会在 Flutter 应用层重新校验。

“仓库详情…”内可为当前 Git 身份选择“未确认（默认限制）”“信任”或“受限”。选择按 Git
common-dir 与 worktree 身份本地保存、可随时改回受限，不会从路径自动推断，也不会改写 Git 的
global/system 配置或 `safe.directory`。未确认和受限状态下，应用自有的外部扩展（自定义操作、

工具栏支持将一个本地分支合并到当前分支；来源有新增提交时会创建显式合并提交。合并冲突会被
读取并展示。在冲突文件上点击右键，可通过“解决冲突 → 打开内部 Diff 工具”左右对比；如果 Git 保留了共同祖先，窗口还可按需展开只读的共同基线预览。两侧标签会按当前的合并、变基、遴选或回滚操作显示实际的基线与待应用来源，避免误解 Git 在不同操作中的 ours/theirs 含义。差异行会高亮；可选用任意一侧，或按第 N 个标准冲突段单独选择一侧，再继续编辑下方合并结果，
然后保存并暂存为已解决；如果结果仍包含任意 `<<<<<<<`、`=======` 或 `>>>>>>>` 冲突标记行，保存前会明确警告并要求再次确认，避免把未处理的标记误当作已解决。macOS 会先把完整结果写入并刷新同目录私有临时文件，再复核已打开目标的 device/inode 并原子替换；写入失败不改变原文件，复核前发生的路径替换会拒绝暂存。文件系统没有“按 inode 条件替换”的单一调用，因此非协作进程恰好在最终复核与 `renameat` 之间替换路径仍是已知极窄竞态；Windows/Linux 尚无等价安全句柄实现，当前会拒绝从内部工具写回冲突结果。二进制、非 UTF-8 或超过内部读取上限的冲突文件仅供查看，避免误写。
主 Diff 和冲突双栏都支持横向查看长行，并以安全宽度上限避免异常输入无界扩张。冲突双栏标题会显示差异数量，并可切换为“仅显示差异”或循环定位上一处/下一处差异；聚焦对比区域后也可用上下方向键定位，筛选和定位不会改变原始行号或写回内容。冲突版本操作在 900px 窗口与 200% 文字缩放下会约束长标签并通过悬停显示全文。可调整分隔条除拖动外还支持方向键和 VoiceOver 增减操作，获得键盘焦点时显示强调色。

`icon.png` 时，首页会以该图片显示圆形仓库图标；图片缺失、不可读或无效时保留默认 Git 图标。每个仓库条目右侧同时显示 Git 读取到的当前分支和未提交文件数；游离 HEAD 与尚未首次提交的分支会明确标注。工作区完成导致 Git 状态变化的操作后会通知首页刷新对应摘要。双击仓库会创建独立的
单仓库工作区窗口，同一路径只允许存在一个窗口；再次双击会把已有窗口带到最前方，重复双击
会合并为同一次启动请求。工作区中的“打开仓库”也使用这一窗口入口。默认每个仓库保持独立窗口；从系统“窗口”菜单选择“合并所有窗口”后，所有已打开工作区会收拢到同一窗口位置，并在标题栏正下方只显示一行紧凑的矩形标签。此后从仓库管理页新打开的仓库，会在 Git 验证成功后自动加入该标签组。标签按钮铺满 29pt 标签条，不在标题栏下方保留额外空隙；标签按窗口顺序等分整行宽度，使用居中文字、直角选中态和 1pt 分隔线，过长名称以省略号显示并保留完整悬停提示。标签支持拖动排序，松手后的顺序会立即保存并在下次启动恢复；每个标签右侧提供关闭按钮，只关闭对应仓库并沿用该窗口的 Flutter Engine 安全清理流程，关闭当前标签后会激活相邻标签。应用不会创建系统胶囊标签条；点击标签或使用标签快捷键时由窗口协调器无动画地立即切换真实的独立工作区窗口，并原位同步仓库标题与选中态，因此每个标签仍保留自己的 Flutter Engine、Git 状态和关闭生命周期。若随后退出应用，下次启动会先等待本批次恢复仓库完成验证，只收拢快照中明确记录的标签组成员，并让拆出的工作区继续保持独立；启动后新开的工作区不会被意外加入。恢复等待最多 30 秒；超时只会结束本批次的合并等待，不会自动关闭工作区，迟到的明确组成员验证完成后仍会重新加入目标组，迟到的独立窗口只完成登记；窗口切换仓库时，迟到的旧状态通知会被忽略，不会误关闭当前工作区；自动刷新重复上报当前仓库时也只更新状态，不会触发窗口去重关闭。应用退出时会保留用户已打开但尚未完成验证的工作区路径，重新运行时继续恢复并验证。已完成工作区和窗口状态也可正常使用与保存。
首页支持将 Finder 中的一个或多个目录拖入窗口；应用只加入能由 Git 识别的仓库根目录，重复或非仓库目录会被跳过。仓库按规范化的完整父路径分组，父目录同名时显示完整路径消歧；可在同一目录组内拖动手柄调整显示顺序，筛选状态下不提供排序。仓库条目可键盘聚焦，Enter/Space 与双击都会打开或激活工作区；首页的“筛选仓库”输入框会在其紧凑工具栏高度内垂直居中文字和搜索图标。

首页仓库条目右侧支持星标收藏和取消收藏；收藏状态只保存仓库路径，不涉及 Git 凭据或仓库内容，并会随本地仓库清单原子写入，在下次启动恢复。收藏按钮可独立点击，不会触发打开仓库或改变 Git 状态。

首页支持创建、重命名和删除用户命名的工作区分组，并可在仓库条目右侧将仓库移入指定分组或恢复为未分组。分组只保存本地仓库路径和分组名称，删除分组不会删除仓库或修改 Git；分组及归属会随仓库清单原子写入并在下次启动恢复。现有按父目录显示的分组仍用于未归组仓库，不会覆盖用户命名分组。

工作区加载仓库成功后会通知首页更新仓库清单；仓库清单采用临时文件原子替换，恢复时保留暂时离线或不可访问的仓库，损坏或 I/O 失败的快照不会被空清单覆盖。添加、选择或排序后的持久化失败会明确提示“当前窗口已保留但尚未写入磁盘”，拖入仓库时不会再同时显示误导性的成功提示；关闭 Engine 前的 flush 不会伪装成功，跨窗口登记只在写盘成功后回复确认。若首页已关闭，窗口协调器会保留该登记，并在首页
重新就绪后再回传，避免并发打开或关闭首页时丢失仓库记录。窗口不会保存 Git 凭据、操作记录或工作区内容。已实现的窗口架构与调试边界
详见 [macOS 窗口模型](docs/MACOS_WINDOW_MODEL.md)。

启动恢复期间，用户主动拆出的工作区会立即从待恢复合并集合中移除，迟到的 Git 验证回调不会把它重新并入。切换到历史提交详情后，macOS 原生文件动作以当前可见的提交文件为目标，不会沿用已隐藏的工作区多选。

## 持续集成

`.github/workflows/quality.yml` 在 pull request 和 `main` 推送时运行格式检查（含 `tool/`）、静态分析、
Flutter 测试和 macOS Debug 构建；`main` 的任务额外运行 macOS 原生 XCTest。每周定时任务及
手动触发会运行本地 bare remote 驱动的 macOS 核心集成测试。分支保护规则由仓库托管平台配置，
应将 `Flutter quality` 设为合并必需检查。

仓库读取性能可使用以下只读命令采样；输出为便于保存和比较的 JSON：

```sh
dart run tool/benchmark_repository.dart /path/to/repository 5
```

Flutter UI 性能专项使用独立的 `integration_test/macos_performance_test.dart`，只创建临时本地
Git 历史，不连接远端或读取用户凭据。它通过 integration_test 的 performance report 记录启动
首帧、到可交互墙钟耗时和 8 次交替历史滚动的精确 P95，并附带启动前、启动后和滚动后的进程 RSS；在支持原生 VM API 的运行模式下还会写出启动后和滚动后的
`.heapsnapshot` 文件，并在报告中记录路径、大小或明确的“不支持”原因。完整结果会写入系统临时目录的
`git_desktop_macos_performance_report.json`。该入口只用于 macOS 性能任务，不纳入普通 PR 门禁。
RSS 是粗粒度进程采样；Dart heap snapshot 只覆盖 VM 堆，不等同于包含 Flutter Engine/native 分配的完整 DevTools 内存快照。

可把一轮结果保存为基线，并在后续采样中以 P95 比较；默认回退超过 15% 会以非零状态退出：

```sh
dart run tool/benchmark_repository.dart /path/to/repository 7 --output /tmp/baseline.json
dart run tool/benchmark_repository.dart /path/to/repository 7 --baseline /tmp/baseline.json
```

基准数据集由固定种子离线生成，绝不会使用远端、凭据、全局 Git 配置或 hooks。生成目标必须
不存在或为空目录；`stress` 档位较大，仅适合定时或手动性能环境：

```sh
dart run tool/generate_benchmark_fixture.dart small /tmp/git-desktop-small 20260907
dart run tool/generate_benchmark_fixture.dart medium /tmp/git-desktop-medium 20260907
dart run tool/generate_benchmark_fixture.dart stress /tmp/git-desktop-stress 20260907
```

首份可重复采样的测量条件与结果见 [性能基线](docs/PERFORMANCE_BASELINE.md)；基准工具同时记录
status、refs、历史读取延迟和 benchmark 进程 RSS，旧结果没有 RSS 时不会伪造内存数值。

近期性能优化：历史 Graph 的后备拓扑会按不可变提交页缓存，提交历史的引用标签使用一次索引，引用导航的本地分支顶层行、平面分区和折叠远端子项按需构建，提交搜索输入在 220ms 后合并发布，提交面板只监听提交所需的会话字段，搜索查询未变化时不会重复发布会话状态，拖拽列宽或切换检查面板时不再重复执行全量计算；推送配置读取远端地址失败时会结束加载状态并允许重试。该优化不改变 Git 读取结果或操作契约。

## 首发目标

LFS 仅保留仓库详情中的既有只读摘要；不规划下载、上传、迁移、清理、配置修改或独立 LFS 管理入口。

托管平台首期范围仅为 GitHub.com（含 GitHub.com 私有仓库）；GitHub Enterprise、企业域名和企业 SSO 不在产品范围内。当前 GitHub.com 仓库浏览与“创建拉取请求…”仍保持“待实现”。后续 PR 入口采用浏览器交接：只接受无凭据的 GitHub.com HTTPS/SSH remote，在用户明确选择 head、base、标题和正文且确认 head 已推送后打开 GitHub.com PR 页面；应用不接入 OAuth、不调用 GitHub API、不保存 GitHub API 令牌，也不自动 Push。

- macOS 优先，Apple Silicon 为第一验证平台。
- 使用系统或用户指定的 Git CLI，Git 仓库是唯一事实来源。
- 完成“打开/克隆 → 查看改动 → Diff → 暂存 → Commit → 分支 → Push”
  的安全闭环，并继续验证认证和恢复路径。
- 架构隔离平台能力，为后续 Windows 和 Linux 留出适配边界。

详细范围、架构、路线图和验收标准见：

- [实施规划](docs/IMPLEMENTATION_PLAN.md)
- [macOS 窗口模型](docs/MACOS_WINDOW_MODEL.md)
- [macOS 原生菜单开发规范](docs/MACOS_NATIVE_MENU_SPEC.md)

Git-flow Finish 的目标选择器会按分支类型优先建议常见集成分支（feature 优先 develop，release/hotfix 优先 main/master），但仍保留全部已加载的本地分支供用户明确选择；Start/Finish 执行前会重新读取状态，预览过期时不会执行检出或合并，并会说明具体安全门禁原因。

Finish 完成、冲突暂停或结果不确定时会显示持久结果面板：冲突状态提供继续合并和中止合并入口，其他未完成结果提供刷新状态入口；这些恢复动作仍以 Git 实际状态为准，不会自动推送或删除来源分支。
